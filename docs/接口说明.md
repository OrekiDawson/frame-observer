# Oreki Frame Observer 接口说明（WorkBuddy 对接）

本文件是给 **WorkBuddy / 脚本侧**看的最小契约。设备侧实现见 `net/FrameHttpServer.java`。

## 0. 连接

```bash
adb -s <serial> forward tcp:8731 tcp:8731
```

之后所有请求打 `http://127.0.0.1:8731`。
服务只绑设备回环地址，**不对局域网开放**；`adb forward` 走的是 USB / 本地通道。

> 注意 Git Bash 会改写以 `/` 开头的参数路径（`/sdcard/...` 会变成 `C:/Program Files/...`）。
> 拉文件时加 `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`，否则 `adb pull` 报
> `failed to stat remote object`。

## 1. 时间基准（最容易被忽略、但决定能不能用）

| 字段 | 含义 | 时钟域 |
|---|---|---|
| `t_mono_ns` / `capture_timestamp_ns` | 采集到该帧的时刻 | `System.nanoTime()` = **CLOCK_MONOTONIC** |
| `source_timestamp_ns` | SurfaceFlinger 交付该帧的时刻 | 同上（`Image.getTimestamp()`） |
| `event_time_uptime_ms` | 系统给的事件时间 | `uptimeMillis`，**同属 CLOCK_MONOTONIC** |
| `wall_ms` | 墙上时钟 | 仅人工对照，**不要用于计算** |

三者在同一时间轴上，因此：

```
事件相对帧的偏移(ms) = (event.t_mono_ns - frame.capture_timestamp_ns) / 1e6
```

`source_timestamp_ns` 与 `capture_timestamp_ns` 之差就是 `capture_latency_ms`
（生产者交付 → 我们取到），它反映的是**采集流水线的排队延迟**，不是网络延迟。

## 2. `GET /snapshot.jpg`

返回最新一帧 JPEG。响应头：

```
X-Frame-Id: 708              # 与 frames.jsonl 的 frame_id 对应
X-Frame-Mono-Ns: 1719346541500
X-Frame-Source-Ns: 1719216037700
Cache-Control: no-store
```

未开始采集时返回 `503` 纯文本。

拉帧脚本示例（Python，无第三方库）：

```python
import urllib.request
r = urllib.request.urlopen("http://127.0.0.1:8731/snapshot.jpg", timeout=5)
frame_id = int(r.headers["X-Frame-Id"])
open(f"f_{frame_id:06d}.jpg", "wb").write(r.read())
```

## 3. `GET /stats`

```json
{
  "target_fps": 60,                 // 我们请求的
  "actual_fps": 8.35,               // 实测的 —— 两者必须分开看
  "width": 540, "height": 1170,
  "frames_available": 708,          // 生产者交付的帧数
  "frames_processed": 708,          // 我们处理完的帧数
  "frames_dropped": 1,              // 主动丢弃（队列满）
  "drop_rate_pct": 0.141,
  "capture_latency_ms": 130.5,      // 最近一帧
  "capture_latency_ema_ms": 1.02,   // 滑动均值 —— 判断抖动看这个
  "encode_latency_ms": 34.6,
  "encode_latency_ema_ms": 9.37,
  "bytes_written": 7975581,
  "write_errors": 0,
  "uptime_ms": 25113,
  "proc": { "java_heap_mb": 7.83, "pss_mb": 59.0, "threads": 14 },
  "capturing": true,
  "session": "/storage/emulated/0/Android/data/com.oreki.frameobserver/files/sessions/20261030-052038"
}
```

**`actual_fps` 偏低不等于故障。** SurfaceFlinger 只在屏幕内容真的变化时才产帧；
停在静态界面时 5~8 fps 是正确行为，不是丢帧。要看吞吐请在有动画/滚动的画面上测，
并同时看 `frames_dropped` 与 `drop_rate_pct` 才是完整判断。

## 4. `GET /events?since=N`

返回第 N 条之后的无障碍事件，`Content-Type: application/x-ndjson`，每行一个 JSON。

```json
{"t_mono_ns":1807604427600,"event_time_uptime_ms":1807604,"record_mono_ns":1807660427600,
 "wall_ms":1793337825695,"event_type":"TYPE_WINDOW_STATE_CHANGED","event_type_id":32,
 "package_name":"com.oreki.antimatterdimensions","window_id":10,"class_name":"b8",
 "view_id":null,"content_description":null,"text":null,"is_password":false,
 "bounds":"0,1048,1080,1428","item_count":-1,"scroll_delta":0,"nearest_frame_id":708}
```

- `event_type`：`AccessibilityEvent.eventTypeToString()` 的原名，不做二次命名。
- `class_name` 是**混淆后的短名**（如 `b8`），不要用它判断业务含义。
- `nearest_frame_id`：事件发生时**已发布**的最近一帧 id。用它做关联即可，
  不要自己插值。注意帧发布有 80ms 节流，所以它可能比真实最新帧落后 ≤80ms。
- 白名单外的包名**不落盘**，所以看到的事件只可能来自
  `com.oreki.antimatterdimensions` 或 `com.oreki.frameobserver`。

### 4.1 `view_tree_snapshot` 事件

`TYPE_WINDOW_STATE_CHANGED` 时额外写一条，`tree` 字段是一棵**有界**控件树的 JSON 字符串：

```json
{"event_type":"view_tree_snapshot","tree":"{\"cls\":\"FrameLayout\",\"id\":null,...}",
 "truncated":false,"nearest_frame_id":708}
```

边界：深度 ≤12、节点 ≤400、单节点文本 ≤80 字，超限时 `truncated:true`。
用途举例：判断游戏当前弹了什么对话框。实测能抓到「在你离开的 2.971 秒里」这类离线结算弹窗，
节点 id 为 `com.oreki.antimatterdimensions:id/titleText`、`...id/awayMessageText`。

## 4.5 `GET /ui` —— 即时控件树（**替代 uiautomator dump**）

```bash
curl "http://127.0.0.1:8731/ui?depth=48&max=3000&flat=1"
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `depth` | 48 | 最大递归深度，1~64 |
| `max` | 3000 | 节点预算，1~5000 |
| `flat` | 1 | `1`=只回有文字/描述/可点/可滚的节点（扁平数组）；`0`=完整嵌套树 |

`flat=1` 返回：

```json
[{"cls":"TextView","id":"...:id/tv_title","text":"Oreki Frame Observer","desc":null,
  "bounds":"44,334,1036,408","clickable":false,"scrollable":false,"depth":5}, ...]
```

**为什么需要它**：`adb shell uiautomator dump` 在**持续动画**的画面上会失败：

```
ERROR: could not get idle state.
```

而且失败时**连 XML 文件都不写**（磁盘上留下的是上一次的旧文件，极易误读成「当前界面」）。
游戏几乎每一帧都在动，所以 uiautomator 在游戏页面上基本不可用。无障碍服务读控件树不需要等 idle。

实测（`oreki_test`，游戏前台、画面持续动画）：`/ui` 一次返回 97 个节点，含完整中文文本与 bounds；
同一时刻 `uiautomator dump` 连续 3 次全部 `could not get idle state`。

**未连接时返回 503**，纯文本说明原因（无障碍服务没启用 / 拿不到活动窗口）。

`flat=0` 的嵌套树结构同 `view_tree_snapshot` 的 `tree` 字段，但**深度上限由参数决定**，
不受自动快照那个 24 的限制。

## 5. `GET /ws`

标准 WebSocket（RFC6455）。服务端只推两种帧：

| opcode | 内容 | 频率 |
|---|---|---|
| `0x2` binary | 一帧 JPEG | ≤12.5 Hz（与 `/snapshot.jpg` 同源） |
| `0x1` text | 事件增量（多行 JSONL） | 有新事件时 |

客户端发文本 `{"cmd":"snapshot"}` 可让服务端立刻补推一帧。`ping` 会被正常回 `pong`。

握手校验（最小客户端可用）：

```
Sec-WebSocket-Accept = base64(sha1(key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))
```

## 5.5 `GET /frame_at?t=<ns>` —— 指定时间点截图回放

按 CLOCK_MONOTONIC 纳秒时刻找**最接近**的一帧。两种用法：

```bash
# 1) 只查索引，返回 JSON
curl "http://127.0.0.1:8731/frame_at?t=1719346541500"
{"requested_ns":1719346541500,"frame_id":708,"capture_timestamp_ns":1719346541500,
 "delta_ms":0.000,"url":"/frames/f_000708.jpg"}

# 2) 直接取那张图
curl -o at_708.jpg "http://127.0.0.1:8731/frame_at?t=1719346541500&raw=1"
```

典型用法：先 `GET /events` 拿到某条事件的时间 `t_mono_ns`，
再 `/frame_at?t=<该值>` —— 就得到「事件发生那一刻」的画面。

`delta_ms` 是命中帧与请求时刻的差；正常情况下应远小于一个帧间隔。
若返回 404 且提示「未开始录制」，说明 `recordToDisk` 被关过，那些帧从未落盘。

### 4.2 按事件自动保存截图（第二阶段）

控件树快照会顺带检查关键词，命中就把**当前帧**另存一份到 `<会话>/events/`，
并在事件记录里给出 `auto_shot` 字段：

```json
{"event_type":"view_tree_snapshot","auto_shot":"events/evt_000708_offline_dialog.jpg", ...}
```

当前规则（关键词 → 标签）：

| 关键词 | 标签 | 含义 |
|---|---|---|
| `在你离开` | `offline_dialog` | 离线结算弹窗 |
| `可以完成` | `challenge_done` | 挑战可完成提示 |
| `你已达成` / `成就已解锁` | `achievement` | 成就解锁 |
| `确定要` | `confirm_dialog` | 需要二次确认的破坏性操作 |

限流：同标签 3 秒内最多一张、单会话最多 200 张、无可用帧时跳过。

> 为什么关键词只收「弹窗/提示类」而不用页签名（如「永恒」「现实」）：
> 页签名在停留于该页的任何时刻都在控件树里，会导致每 3 秒存一张，既灌满磁盘又无信息量。

## 6. 控制端点

| 端点 | 作用 | 备注 |
|---|---|---|
| `POST /capture/stop` | 请求停止采集 | 实际停止由设备侧服务执行 |
| `POST /capture/record?on=0` | 关掉逐帧落盘（仍保留预览与 snapshot） | 长时间观察时省磁盘 |
| `POST /capture/record?on=1` | 恢复落盘 | |

**没有 `/capture/start`。** 投影授权必须由人在设备上确认，远程触发等于绕过系统授权流程。

## 7. 拉取会话数据

```bash
export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'
adb pull /sdcard/Android/data/com.oreki.frameobserver/files/sessions ./sessions
```

文件含义见 `README.md` 的「数据输出」一节。JSONL 是**追加式**的，
录制中断时截断处之前的行全部可解析。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `/snapshot.jpg` 返回 503 | 没开始采集，或已停止 | 在 App 里点「开始捕获」并授权 |
| `actual_fps` 只有个位数 | 画面静止，SurfaceFlinger 不产帧 | 正常，不是故障；换有动画的页面测 |
| `capture_latency_ms` 偶发上百 ms，但 ema 很低 | 单帧排队抖动 | 看 `capture_latency_ema_ms` 判断趋势 |
| 只有 `stats` 没有 `events` | 无障碍服务没开 | `settings put secure enabled_accessibility_services com.oreki.frameobserver/com.oreki.frameobserver.a11y.ObserverA11yService` 且 `accessibility_enabled 1` |
| `adb pull` 报 `failed to stat remote object` | Git Bash 路径改写 | 见第 0 节 `MSYS_NO_PATHCONV` |
